# PDF互動講義批改系統

把教師的 PDF 講義變成可分版管理的線上互動教材。一個版面可加入多份 PDF 教材，各教材的問答區、筆跡、課堂狀態、作答與草稿彼此隔離。學生以暱稱進入，針對教師放置的問答圖釘輸入文字或拍照上傳；教師可在平板上以觸控筆直接閱讀 PDF、書寫、標記圖釘、查看答案與批改。

## 檔案

- `index.html`：原生 HTML、Vanilla CSS 與 Vanilla JavaScript 前端。
- `Code.gs`：Google Apps Script API，使用 Google 試算表保存索引，使用 Google Drive 保存 PDF、照片與大型 JSON。
- `rdq/`：已確認的 RDQ 需求規格卡。
- `assets/`、`css/`、`js/`：預留的靜態資源資料夾；目前前端維持單檔，方便 GitHub Pages 或本機開啟。

## 使用方式

### 本機示範

直接開啟 `index.html`，在連線設定視窗選擇「本機示範模式」。本機模式的 PDF、照片、版面與批改資料只保存在目前瀏覽器，適合先測試操作流程，不代表跨裝置同步已完成。

### GAS 部署

1. 建立一份新的 Google 試算表。
2. 選擇「擴充功能」與「Apps Script」，將 `Code.gs` 全文貼上並儲存。
3. 在 Apps Script 編輯器執行 `initDatabase` 一次，完成資料表與 Drive 權限初始化。
4. 選擇「部署」、「新增部署」、「網頁應用程式」。
5. 執行身分選「我自己」，誰可以存取選「任何人」，完成部署。
6. 前端以 `index.html` 的 `DEFAULT_GAS_URL` 作為預設網址；分享網址參數與設定視窗保存的網址可覆寫預設值，重新部署 GAS 後可直接更新設定或替換常數。
7. 首次使用時，GAS 會自動建立「系統設定」、「公告連結」、「教材版面」、「問答區」、「答案遮罩」、「教師手寫」、「課堂狀態」、「作答紀錄」與「檔案索引」工作表，以及 Drive 根資料夾。
8. 請在「系統設定」工作表填入 `AdminPassword`，教師入口與所有教師管理操作才會受到密語保護。
9. `Code.gs` 更新後，請在「部署」中建立新版本；快取與背景佇列才會套用到 Web App。

### 公告多連結排查

1. 若儲存後只剩第一個連結，先確認實際連線的 GAS 網址；分享網址與瀏覽器保存的設定會覆寫預設網址。
2. 將最新 `Code.gs` 更新至原 Apps Script 專案，選擇「部署」、「管理部署」、編輯原網頁應用程式，再選「新版本」並部署，以保留原網址。只儲存程式碼不會更新既有網頁應用程式。
3. 確認「公告連結」工作表已自動補上「連結資料」欄位。重新編輯公告並填入多個連結，儲存後該欄應包含完整連結 JSON。
4. 重新整理教師端，再開啟學生端確認每個連結與名稱。先前未存入的連結無法自動恢復，需重新填寫。
5. 前端會比對後端回傳清單與送出的連結。若不完整，表單會保留並提示部署檢查，不會顯示儲存成功；請勿關閉或重新整理尚未成功儲存的表單。

### 連線診斷與初始化

- 執行 `node tests/diagnose-network.js --include-file` 可依序量測預設 GAS 的公開清單、第一個版面、課堂同步與第一份 PDF。只執行讀取，不輸出教材或學生內容。若前端使用其他 GAS 網址，可先設定環境變數 `PDF_GAS_URL`。
- 加上 `--compare-post` 可比較同一份公開資料的 GET 與 POST 讀取。每次請求上限九十秒，結果列出狀態碼、耗時與回應大小；這是診斷工具，不是多人負載測試。
- 本輪後端的 `ping` 回應包含 `apiVersion`，值為 `2026-09-10-network-v2`。部署後可用這個欄位確認正在執行新版，而不只確認程式碼已儲存。
- 資料表初始化依結構版本保存完成記號，快取過期不再重跑整庫遷移。變更資料表結構時須更新 `DATABASE_READY_CACHE_KEY`；手動刪除或改壞資料表後，可在 Apps Script 執行 `initDatabase` 重新檢查與補齊。
- 前端請求上限調為六十秒，以容納已觀察到的慢回應；這不會縮短 GAS 本身的執行時間。唯讀請求最多嘗試兩次，寫入仍由既有補傳佇列處理。

### 入口分流

- 根網址是公開學生入口，免密碼顯示公告與所有啟用中的教材版面。
- 學生可直接使用 `?view=student&board=...` 分享網址進入，不需要帳號或密碼；個別學生頁不顯示公告。
- 教師由入口網站的「教師入口」開啟密語視窗；驗證成功後可使用管理、編輯與課堂頁。
- 教師產生的分享網址與 QR Code 固定指向學生版，不提供教師管理網址。

## 資料設計

- 「教材版面」保存每一版的名稱、說明與版面層級索引；「課堂教材」保存同一版面下每份 PDF 的名稱、說明、排序與 Drive 檔案索引。
- 「問答區」保存 `materialId` 及相對於 PDF 頁面的圖釘百分比座標，因此不同教材不會互相顯示，縮放後仍能對準原位置。
- 「答案遮罩」獨立保存 `materialId`、頁碼與矩形百分比座標；教師在編輯頁拖曳建立遮罩，課堂投影預設遮住且可由教師在目前裝置揭示，學生頁固定遮住不可自行撤下，編輯頁與批改彈窗維持原文可見。
- 學生點選問答圖釘後，PDF 上的目前圖釘會高亮，作答卡會自動聚焦；手機作答卡提供上一題／下一題導覽，依目前教材的頁碼與題目順序切換。
- 「教師手寫」與「課堂狀態」保存 `materialId`，教師切換教材時只讀取目前教材的頁面與筆跡；學生端約每 3 秒嘗試同步教師切換的教材，但頁碼、縮放與閱讀位置保留在學生自己的裝置，自己的作答清單約每 6 秒嘗試更新一次，實際更新速度仍受請求耗時影響。
- 「作答紀錄」與學生草稿保存 `materialId`，作答 ID 也依教材隔離；內容包含暱稱、文字答案、照片檔案索引、教師批改狀態與評語。
- 「公告連結」是公開入口共用的學生常用入口，保存標題、選填簡要說明、最多 8 個 `http`／`https` 連結及各連結名稱、置頂、排序與狀態；只有教師管理頁可新增、修改、刪除及調整順序，教師課堂公告抽屜只提供安全的新分頁開啟，個別學生頁不掛載公告。
- 線上模式的公告直接讀寫 GAS，不進入離線快取或背景補傳佇列；本機示範模式則沿用 IndexedDB 保存示範資料。
- 「檔案索引」保存 Drive 檔案 ID 與 `materialId`。照片、PDF 與大型 JSON 不直接塞進試算表儲存格。
- 教師可從版面卡片或編輯頁永久刪除版面；刪除時會一併清理 PDF、問答區、學生作答、照片、教師批改、手寫筆跡、JSON 附件、Drive 版面資料夾與本機快取。
- 所有新增、修改、封存、刪除教材、刪除版面、作答與批改都先寫入瀏覽器 IndexedDB，再依序放入 outbox 背景傳送；傳送失敗會保留佇列，不用遠端回應覆蓋較新的本機內容，並以 mutation ID 讓 GAS 重試具備冪等性。
- 教師筆跡以相對座標 JSON 保存，課堂輪詢只在版本變更時讀取 Drive；已讀過的 PDF 與照片也會以檔案 ID 快取在本機。
- 學生端課堂同步只下載目前頁面的教師筆跡，並先顯示本機快取的頁面內容；網路更新完成後再替換為最新版本。
- 學生端與課堂端呼叫 `classroomPulse` 取得版本與課堂狀態；新版以 `includeChanges` 要求有變更時在同一個回應附上資料，省去第二次請求，無變更時仍維持輕量回應。舊版後端則沿用兩段讀取。
- 試算表資料會短暫快取 3 秒，因此直接手動修改工作表後，最多可能延遲 3 秒反映；作答計數另以 5 秒快取降低課堂輪詢負載。

## 第一版邊界

- 主要目標為單班約 30 人的課堂使用。
- 教師端支援手寫筆、螢光筆、圖形、橡皮擦、本頁清除與全部清除；系統依輸入來源分流，觸控筆或滑鼠直接書寫，手指可用來滑動並捏合縮放 PDF。
- 課堂與批改區預設筆畫粗細為 2，可再選擇 4、6、8；手指預設用於捲動與縮放，也可由工具列切換為手指書寫；橡皮擦請由工具列或鍵盤 `E` 切換，避免提筆再落筆被誤判為雙擊。
- 學生不使用畫筆，學生答案以文字與壓縮照片為主。
- GAS 版採定時同步，不做多人同一畫布的即時共同書寫；學生端約每三秒嘗試取得教師目前教材與該教材的頁面筆跡，同一代只保留一個同步請求，失敗後延長重試間隔，教材切換或頁面隱藏時會取消過期請求。
- 教師課堂 PDF 的頁碼、縮放與手寫標記採落筆後批次同步；學生端只跟隨教師切換的教材，自己的頁碼、縮放與閱讀位置不被教師狀態覆寫，網路逾時或斷線時改用本機快取，恢復連線後再由 outbox 補傳。
- 不納入 Firebase、Google 帳號登入、AI 評分、語音回答與正式版本歷史。
- 學生照片預設在瀏覽器端壓縮至寬度 800px，並限制每題張數與大小。

## 注意事項

學生只填暱稱時，身分辨識屬於課堂活動等級，不是正式帳號系統。若日後要長期保存成績、跨班管理或公開提供服務，應追加真正的權限驗證、資料保留政策與更嚴格的檔案存取規則。
